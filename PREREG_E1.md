## 1. Question
Does adding lambda * SIGReg (Epps-Pulley on random 1-D projections, evaluated on a BatchNorm projector head) to the label-free AR objective improve latent separation ACROSS GEOMETRIES -- the gap Proposition 1 leaves open (it bounds separation across load cases on a shared stiffness matrix only) -- without degrading the in-band gate metrics? (Cross-resolution transfer is not measurable in 2D; it enters at the 3D confirmation stage, Sec. 5.)

## 3. lambda and head width (pilot, then frozen)
`scripts/e1_lambda_pilot.py --head-width auto`, seed 0, 20 epochs, trained on pool[:512] of the E1 split and validated on pool[512:640] -- labelled instances disjoint from E1's validation set (the pilot never sees E1's test data); it buys no labels and leaves the corpus manifest unchanged (both recorded in its JSON). It trains under the arms' numeric policy (TF32 as the configuration sets it) and learning rate (`experiments.e8.ar_lr`, the key the E8 AR units read; default 1e-3), with the same model construction, seeding, loss and head as the arms' seed 0; its warm-up/cosine schedule spans its own 10,240 steps. Head width: the intrinsic-dimension rule (round(2 x TwoNN ID) if ID < dim/4, else 0 = full width) applied to the lambda = 0 pilot model's latents on the pilot-validation instances -- same domain, same code, measured before any SIGReg candidate is trained, so lambda is selected under the head the shaped arm uses. lambda: the LARGEST value in {0.01, 0.1, 1.0} whose pilot-validation displacement error stays within 5% relative of the lambda = 0 pilot. If none is admissible, E1 ends at the pilot with the verdict NO-GO-AT-PILOT; the pilot JSON (`selected_lambda: null`) is the publishable record and no arm is trained. ## 4. Measurements
- In-band validation displacement error and relative energy gap of every seed (the E8 AR cells of each arm's report).
- Cross-geometry separation S (`scripts/latent_separation.py --subset val`, every state of every arm): pooled (instance-mean) latents of the 256 validation instances, grouped into quartile bins of the first principal component of the centred 6-D geometry descriptor; S = mean silhouette of the bins in latent space. Reported beside S: PC1 loadings and variance share, leave-one-out 1-NN bin accuracy, linear-probe R^2 of the descriptor, SIGReg monitors, and an instance-level 95% interval (stratified half-sampling without replacement, centred on S; reported only). Distances are computed in float64 on centred latents; each separation file records the SHA-256 of the state it measured and the canonical SHA-256 of the configuration it used.

## 5. Kills and GO
- **K1 (parity; decided by the PI on 29 September 2026, before stamping):** for each of the in-band displacement error and the in-band energy gap, compare SEED MEANS (the Phase-2 aggregation rule); K1 fires if, for either metric, the relative change of the AR+SIGReg arm's seed mean over the AR arm's exceeds max(10%, 2 x SE_rel), where SE_rel = sqrt(s_AR^2/3 + s_SIG^2/3) / mean_AR with s the seed-to-seed SAMPLE standard deviations (n - 1) of each arm => latent shaping is retired for the AR loss. The threshold actually applied (the resolution) is reported with the verdict, as are the per-seed changes (informational). Why: under the corrected objective the AR seed spread is large (3D Phase-2b: displacement CV 9.4%, energy-gap CV 25%); the r12 per-seed 10% rule would fire in 90% of trials with no true effect. Properties of this rule by simulation (200,000 trials, 3 seeds per arm, log-normal seed noise): false kill with no true effect about 10% at Phase-2b-like noise and about 1% at the Phase-1 2D noise; median effective band 14% (displacement) and 37% (energy gap) at Phase-2b-like noise, 10% at Phase-1 2D noise; a true 50% energy-gap degradation is caught with probability about 0.55 at Phase-2b-like noise. The 2D seed noise under the current code is not known before the base run; the threshold is computed from the runs' own seeds. A non-finite per-seed metric of the AR+SIGReg arm is a divergence and counts as K1 firing (its separation is then not evaluated); a non-finite value in the AR arm voids the comparison (refused, reported as a deviation).
- **K2 (no effect):** S(AR+SIGReg) - S(AR) <= 0 at every seed => the cross-geometry claim is not supported.
- **GO (2D stage):** S improves at every seed by at least the effect floor max(0.02, 2 x the AR arm's seed-to-seed SAMPLE standard deviation of S (n - 1)) -- three same-signed noise-level deltas are not a GO -- and K1 does not fire.
- 3D confirmation stage (only after a 2D GO; its own pre-registration): GO additionally requires the P3 transfer ratio not to worsen beyond the band at any seed.
- Adjudication: `scripts/adjudicate_e1.py`; it refuses reports that are not stamped, guard-verified runs of this file, a base report that carries a loss specification or a shaped report that is not the AR+SIGReg(head) arm with a filled lambda and width (swapped inputs would flip the sign of every kill), reports that differ beyond `pretrain.loss_spec` (corpus manifest, split, seeds, schedule including `e8.ar_lr`, dims), non-finite per-seed metrics, and non-finite S; separation files from the other arm, not measured on `val`, not valid (`S_valid` false or smoke), on fewer than the split's 256 instances, measured with another configuration or on another corpus (data manifest SHA-256 against the report's datasets), or on a state other than the one the report trained (state SHA-256 against the report's `d9_restart` record); a non-finite S is accepted only for a shaped arm that diverged (K1). S values are paired with seeds through the state path each separation file records.

## 6. Execution mechanics (exact)
- Configurations are generated, not hand-edited (`scripts/make_e_series_configs.py` from `configs/phase1_rec8_v2.json`): E8 as AR pretraining only (`experiments.e8.ar_only = true`), every other experiment disabled, no P3 block (no transfer set in 2D), guard on `PREREG_E1.md`. A test regenerates the committed configurations byte for byte with the stamping-time values.
- Economy: label policy `asis`; the runs buy nothing and each solve ledger reads 0 (the validation labels exist from Phase 1). Any non-zero ledger line is a deviation to explain.
- Stamping: the generator fills this file's parameter line (Sec. 2) and the configurations from the pilot JSON; this file carries one labelled line per configuration (below); `fejepa prereg configs/<arm>.json --stamp --prereg-file PREREG_E1.md` fills the line named after the configuration; the guard refuses every arm while any line is unstamped, so no arm can run before all three are frozen. Then commit, tag `prereg-e1`, push, and verify the remote tag before any GPU time. This file's SHA-256 (last line) is recorded in the stamp commit itself, computed over the file with that line reading `PREREG_E1_SHA256 = <record after commit>` (a file cannot contain its own hash).
- Runs: `run-config` once per arm, in-checkout, sequential, `--reuse-states` only for a restart (RUNBOOK_E_SERIES Sec. 1d). On CUDA a run is not bitwise reproducible (atomic reductions in the attention backward); a restarted unit resumes from its epoch checkpoint and the report records it (`d9_restart`).
