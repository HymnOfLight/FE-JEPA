# PRE-REGISTRATION W9 -- unlabelled pool size (C1) and a mesh-independent scale (S)

**Branch:** wp9-pool. **Status:** r2 DRAFT (2 October 2026), not stamped; the six CONFIG_SHA256 lines below are open. Stamping fills them all at once, before session 1 (Sec. 8); post-stamp criterion changes are prohibited. **Authority:** this English file governs. **Publication:** every outcome below is publishable.

## 1. Questions
- **Q1 (C1).** At a fixed budget of 204,800 label-free AR steps per seed, does training on a larger unlabelled pool lower the relative energy gap in band (and, secondarily, in the tail and on held-out families)? Every deciding run so far trained on 1,024 instances; the theory note's claim that AR can use arbitrarily many unlabelled instances has not been tested.
- **Q2 (S).** Does decoding with a scale that does not change with the mesh, and feeding the loads in a form that does not change with the mesh, remove the GROWTH of the error on a finer mesh than training saw (KP4's failure mode; wp8 post-hoc reading 4e found it as an amplitude deficit in 3D)? Asked only if session 1's rule 1 admits it (Sec. 4).

## 2. Arms
All arms: E1's 2D base configuration otherwise -- `runs/data2d` (n = 30,000, manifest SHA-256 `3553396d183115b843512a35cba1a1e8448b9e83e10c1d1a5b02b235a7c79d26`), split n_val = 256 / seed 1, model dim 256 / depth 8 / heads 8 with load-summary and geometry channels, AR objective (`AR_CONFIG`), AdamW lr 1e-3 with the warm-up/cosine schedule over each run's own 204,800 steps per seed, TF32 on, three seeds; pools are nested prefixes of the same pool permutation (pool[:N]).

Runs only if rule 1 admits S. |

Exactly one of the two largest-pool configurations runs; "N_max" below is the one that ran. The factor 1/64 only sets the level of S's decoded output: over 256 training-family instances drawn in the sandbox (2 October 2026), max|F| / sum|F| (component-wise) had median 0.0156 (10th-90th percentile 0.0098-0.0226, i.e. 0.63-1.45 times 1/64) and grew with the mesh size, so at training mesh sizes S asks the network for outputs of E1's level on the median instance; the scale of E1's arms shrinks with the element size, S's does not. S changes the decode scale and the load inputs together, and H2 tests them together. The configurations are generated (`scripts/make_w9_configs.py`, from `configs/e1_2d_base.json`, which it refuses unless its canonical SHA-256 is PREREG_E1's stamped `4dfdea42...`); a test regenerates them byte for byte and checks that each differs from E1's base only in the keys named here (`evaluation`, `out`, `prereg_file`, `_comment`, `e8.pool_sizes`, `e8.ar_epochs`, `e8.reuse_from`, `e8.seed_offset`, and S's three model keys).

The 1,024 arm reuses E1's states because the default training path is bitwise unchanged against `wp8-lejepa` (Sec. 9); the N_max and 4,096 arms train with the same code, corpus, seeds and schedule length. S is compared with a freshly trained baseline on fresh seeds, not with E1's states: rule 1 admits S by reading E1's states on F5, and comparing S with the very states that were selected for a large fine-mesh error would bias H2 toward support. Activation checkpointing (rule 3) recomputes the same operations (bitwise identical on CPU, tested); on CUDA any two runs differ at round-off (atomic reductions), with or without it; E1's states were trained with it on.

## 3. Evaluation sets
- **In band:** E1's validation split (256 instances).
- **OOD-2D v1** (`src/fejepa/fe/ood2d.py`; evaluation only -- no training and no hyper-parameter reads them; rule 1 reads E1's states' errors on F5, which is why H2's reference is the fresh baseline): five families of 256 labelled instances, each changing one attribute of the training family and drawing the others from the training ranges: F1 4-6 holes (training 0-3); F2 slender plates, width 3.0-4.5 and height 0.6-0.8 (1.5-3.0, 0.8-1.5); F3 1-3 holes, all large (0.16-0.22) or all small (0.03-0.06) x min(w, h), one class per instance with probability 1/2 (0.06-0.16); F4 Poisson ratio 0.40-0.45 (0.25-0.38); F5 mesh size 0.025 (0.05-0.12). Secondary differences that come with the changed attribute: F1's radii are slightly smaller on average (0.106 against 0.109 x min(w, h)); F3 has no hole-free plates and its large holes may leave an edge ligament of 0.02 x min(w, h) (training at least 0.04).
- **R** (remesh set, evaluation only): 16 training-family geometries, each meshed at h = 0.12, 0.085, 0.05, 0.035, 0.025 (80 instances; only the mesh changes).
- The sets are defined by the committed generator and seeds (91001-91006) and generated once on the box in session 1 (`scripts/w9_make_ood2d.py`), labelled there by direct solve (the labels' cost is in each manifest's ledger; the runs buy nothing). Each manifest pins every file by SHA-256; every run verifies its holdouts before training (family name, files, labels) and records each manifest's SHA-256; the session-2 plan checks the manifests on disk against session 1's record before any arm runs; the adjudication requires every arm to report session 1's manifests.

## 4. Session 1 and the selection rules
Session 1 (`RUNBOOK_W9.md` Sec. 1) trains nothing. Its readings that select what session 2 runs are read by `scripts/w9_session1_decisions.py`, committed on 1 October 2026 (`1b32a34`, Stage 0a) before any reading existed and unchanged since; each rule is evaluated on its own, so a missing input leaves only the rules that read it undecided:
1. **S enters** iff E1's base states show, on F5 against in band, a displacement-error ratio (seed means) >= 1.5 AND a median c* on F5 >= 1.10. Then both `w9_b_n1024` and `w9_s_n1024` run.
2. **N_max and the schedule:** 25,600 with three concurrent workers if their host and device memory fit within 80% of the limits (memory audit C0.6), else 25,600 one seed at a time, else 12,800 with three workers, else one at a time; else no session 2 (the pool design is revisited).
3. **Activation checkpointing off** iff the AR step is >= 1.3x faster without it in E1's worker set-up AND rule 2's choice still fits without it. Undecided (no timing): on. The plan keeps it on for any other arm that would not fit without it (the same memory test).
4. and 5. Predictions only (training/validation gap ratio; the CG energy-drop score's rank correlation, for C2 later): no effect on any arm or criterion.

`scripts/w9_session2_plan.py` turns the decisions into session 2's command list and refuses to plan (STOP) unless: the required session-1 steps exited 0; the decision file is the frozen rules' output (their SHA-256) on the session's own readings (theirs), recomputed and identical, written on `prereg-w9`, which the checkout must also be; rules 1-2 are decided and a pool was found; the evaluation sets are complete and the manifests on disk are the record's; E1's validation arrays were reproduced (Sec. 9); a GPU and E1's torch version are present; every selected configuration passes its dry run against this file. Workers and checkpointing are run-time settings (`run-config --workers`, `--activation-checkpointing`), recorded in each report; they change scheduling and memory, not the operations a unit computes (bitwise identical on CPU with single-threaded torch; on CUDA any two runs differ at round-off).

## 5. Measurements
For every arm, seed and evaluation set: the frozen metric suite per instance (relative energy gap, displacement relative L2, von Mises relative L2, peak von Mises error, critical-region recall), and the amplitude readings per instance (c* per load case, the battery form c_b, displacement error and energy gap after scaling each load case by its c*, energy norms of prediction and exact solution). Per-seed values are means over the set's instances; arm values are seed means; tails are per-seed 90th percentiles of the per-instance energy gap (linear interpolation), seed-averaged; the F5 / in-band ratio is formed per seed from the seed's mean displacement errors.

## 6. Hypotheses and verdicts
Noise guard (the E-series rule, PREREG_E1 r13): for arm values A (new) and B (reference) from three seeds each, rel = mean(A)/mean(B) - 1 and SE_rel = sqrt(s_A^2/3 + s_B^2/3) / mean(B) with sample standard deviations (n - 1); tau = max(10%, 2 x SE_rel). "Lower beyond the guard" means rel < -tau; "worse beyond the guard" means rel > tau. The tau applied is reported with each verdict, as are the per-seed values.
- **H1 (C1; primary).** Reference: the 1,024 arm. **H1 is SUPPORTED** iff the N_max arm's in-band relative energy gap is lower beyond the guard; otherwise **NOT SUPPORTED** (reported as "worse" if it is worse beyond the guard). A non-finite per-seed value of the N_max arm is a divergence: NOT SUPPORTED (diverged); a non-finite value in the reference voids the comparison (H1 not evaluated). Properties of the rule by simulation (400,000 trials, three seeds per arm, log-normal seed noise): at E1's measured 2D noise -- in-band energy gaps 0.0374 / 0.0405 / 0.0371, a coefficient of variation of 4.9% with the guard's sample standard deviation (4.0% with the population one) -- a support without a true effect occurs in about 0.4% of trials, and a true 10% / 15% / 20% reduction is detected in about 48% / 91% / 99.7%; at 10% noise the false-support rate is about 4% and the detection rates 29% / 52% / 75%. Three seeds pin the noise poorly (a 95% interval for the coefficient of variation from E1's three values is about 2.5% to 31%); the guard uses the runs' own spread.
- **H2 (S; primary if S runs).** Reference: the fresh baseline `w9_b_n1024` (same seeds 3-5, pool, schedule and code; only S's three keys differ). **H2 is SUPPORTED** iff all of: (i) S's F5 displacement error is lower beyond the guard; (ii) S's F5 / in-band displacement-error ratio is lower beyond the guard (the growth itself shrinks, not only both levels); (iii) K1, the E-series parity rule on both in-band metrics: neither S's in-band energy gap nor its in-band displacement error is worse beyond the guard. Otherwise NOT SUPPORTED, with the failing conditions named. A non-finite per-seed value of S fails the condition it enters (reported as diverged); a non-finite value of the fresh baseline voids the comparison (H2 not evaluated). H2 reads the same 256 F5 instances and validation split that rule 1 read: the fresh seeds of both arms remove the selection on E1's training noise, and the instances' own difficulty enters both arms alike.
- Two questions, two verdicts; no multiplicity correction (they are separate claims, each reported with its own threshold). A primary arm without a report, or with a report the adjudication refuses (Sec. 8), leaves its own hypothesis NOT EVALUATED (recorded); the other is still adjudicated.

## 7. Secondary readings (reported, no verdict; exploratory)
- C1: the in-band tail; every OOD family's energy gap and displacement error; the c*-scaled readings; the curve 1,024 -> 4,096 -> N_max for every metric; each comparison with the Sec. 6 guard computed and stated (about a hundred comparisons: exploratory, not tests).
- C1 against session 1's prediction (rule 4): the predicted reading beside the observed in-band change.
- The fresh baseline against E1's states (in band; different seeds): a check of the reuse and of the software stack.
- S (if it runs): its readings on F1-F4 against the fresh baseline (does S cost anything elsewhere); mechanism -- the median c* on F5 (near 1 if S removes the amplitude deficit) and, on R, c_b and the predicted energy norm per mesh size relative to each geometry's coarsest mesh, beside the exact solution's own ratio (S's should follow the exact one; the baseline's is expected to fall as h shrinks); the F5 / in-band ratios of the 1,024 arm, the fresh baseline and S.
- Everything per seed as well as seed-averaged.

## 8. Execution mechanics (exact)
- Stamping, before session 1: `fejepa prereg configs/<arm>.json --stamp --prereg-file PREREG_W9.md` for all six configurations (each fills the line named after it; the guard refuses every arm while any line is open); this file's SHA-256 (last line), computed over the file with that line reading `PREREG_W9_SHA256 = <record after commit>` (a file cannot contain its own hash); commit; tag `prereg-w9`; push; the remote tag is verified before session 1. The branch is frozen until session 2 has returned: the box checks that `git describe --tags --match prereg-w9` prints exactly `prereg-w9`. Session 1 and session 2 then run on that commit, in one visit or two.
- Session 2 (`RUNBOOK_W9.md` Sec. 2): the commands `scripts/w9_session2_plan.py` writes, in this order: the 1,024 arm (evaluation only, minutes), N_max, the fresh baseline and S (if admitted), 4,096 -- the primary comparisons first. Each is a `run-config` of a stamped configuration with the run-time settings of rules 2 and 3; a restart uses `--reuse-states` (D9; recorded in the report). The command script checks before every arm that the code is still `prereg-w9`, keeps every attempt's log and time-stamps each attempt; it skips an arm whose report is complete and restarts one whose states exist without a report.
- Economy: label policy `asis`; every run's solve ledger reads 0 (the validation labels exist; the holdouts' labels were bought at generation and are counted in their manifests).
- Adjudication: `scripts/adjudicate_w9.py`, from the two returns. It recomputes session 1's decisions with the frozen rules from the returned readings. It refuses to adjudicate at all when the session is not intact: a decision file that differs from the recomputation, was written by other rules, from other readings, or on another commit than `prereg-w9`; an incomplete OOD-2D record or an R manifest that is not the record's; a plan made from another decision file; a session-2 return without its plan, status file or provenance file; a report the provenance file lists that is missing or has another SHA-256; an arm the status file shows finished without its report. It refuses a single report -- leaves it out and records why -- that is not a guard-verified run of this file under its own CONFIG_SHA256 line, ran on another commit, differs from E1's base beyond the keys of Sec. 2, is not the stamped arm for its role, ran on another corpus or seeds, does not hold one evaluation per seed, or whose holdout manifests are not session 1's; a 1,024 arm that is not E1's states (SHA-256 against E1's records copy, reused through that same file) or does not reproduce E1's validation arrays (largest relative deviation <= 1e-4; a non-finite value never reproduces); an N_max or S arm the rules did not select. It records as deviations: a planned arm without a report, run-time settings other than the plan's, restarts and repeated attempts, resumed units, a non-zero solve ledger, and a software stack or GPU other than E1's (H1 compares with states trained on E1's stack). Secondary readings never block a verdict. The verdict file records every input's SHA-256 and the adjudicating code's.

## 9. Preconditions
- Suite green on the stamped head.
- The default training path is bitwise identical to `wp8-lejepa` (`scripts/regress_against_branch.py`, CPU, both sides in their own processes, fresh and restart passes): on a miniature of E1's base configuration (2 states, 162 numbers) and of the Phase-2b configuration (6 states, 2,590 numbers) -- identical (`records/wp9/regression_wp8_*.json`; `records/wp9/README.md` names the code they ran). This licenses the reuse of E1's states.
- On the box before session 2 (checked by `w9_session2_plan.py`): every required session-1 step exited 0; the five OOD families and R generated and verified; E1's per-instance validation arrays reproduced by the C0 evaluation of E1's states (largest relative deviation <= 1e-4; inference only, so 0 or round-off is expected); rules 1-2 decided; a GPU and E1's torch version.
- Cost: about 3 h per trained three-seed arm with three concurrent workers (E1's base arm took 2 h 58 min for 3 x 204,800 steps on this box), plus minutes per worker of data preparation at 25,600 and minutes per state of evaluation on 1,616 instances; N_max one seed at a time, if rule 2 so decides, about 5-9 h (unmeasured); the 1,024 arm, 10-30 min. Session 2 in all: about 7 h without S, about 13 h with S; 2-6 h more if N_max runs one seed at a time. Session 1: about 1 h.
